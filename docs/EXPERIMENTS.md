# 如何把算法与系统实验做成可信的证据

每次记录应含：问题、预测、输入/规模/分布、版本、环境、重复次数、原始结果、正确性检查、解释与局限。先看正确性，再看速度。

## 缓存模型

模型用元素索引当地址；直接映射，初始为空。4行、每行4元素时，连续访问0..63应16次未命中、48次命中。8×8列式访问同一集合有64次未命中。增到16行后，整个工作集可驻留，列式仍应只有16次冷启动未命中。

这些是模型下可手算的结论，不是CPU的缓存未命中率。模型没有预取、多级缓存、相联替换、TLB、字节大小或系统调度。预测真实CPU性能必须运行本机实验并核验变量。

## C布局对照

`locality.c`用两个相同大小的后继索引数组形成单环；顺序环和打乱环都访问n个相同节点各一次，并求相同校验和。两边都是依赖前一步地址的指针追逐。它隔离访问顺序，不包括独立节点malloc、复杂链表删除或Python对象开销。

程序先构造、暖机、验证，再交替测量顺序；输出每轮耗时和校验和。TIME_UTC是墙钟，不是硬件性能计数器，也不是严格单调时钟。负时间会报错；小输入的计时噪声较大。可在Linux中自行改用CLOCK_MONOTONIC并说明移植边界，或用系统工具进一步观察。固定seed的LCG加模运算适合教学复现，不作为高质量随机数来源。

运行者补充CPU型号、OS、编译器和编译选项，保留至少5次原始值，报告中位数及范围。没有控制所有硬件因素时，不应把速度差完全归因为缓存命中率。

## Python排序

数据构造、正确性断言不计时；返回列表的分配和排序计时；固定数据分布/种子，轮换顺序，重复5–7次。每次都与`sorted`核对。内建排序由C实现，对比结果同时包含算法、解释器和实现差异；不能归结为单一算法优势。

## SQLite索引

内存数据库、5万条合成记录、查询bucket=42，索引前后独立核对结果，打印查询计划与原始时间。该实验不测磁盘I/O，排除了创建索引与写入维护成本，且查询选择率较高。要研究普遍价值，应追加不同选择率、更新负载和文件数据库实验。

## 第一周的具体安排

1. 解释127、128、255的8位模式，独立写出补码推理。
2. 学复杂度和不变量，用空数组、重复、负数、逆序测试两种排序。
3. 先预测再运行缓存对照；把原预测和结果差异保存为一条学习记录。
4. 导出备份并导入成长系统；在每周复盘中选定一个下一步任务。
